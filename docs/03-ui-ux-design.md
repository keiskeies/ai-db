# AiDB Studio — UI/UX 设计

> 版本：v0.3 · 关联：[功能规格](./02-feature-spec.md) · [Agent](./04-ai-agent-design.md)

## 1. 设计原则

1. **数据库工具的专业密度**：信息优先，紧凑但不拥挤；键盘可达；不牺牲可读性。
2. **Agent 是一等公民，不是浮窗**：独立右侧面板/移动端主 Tab，具备完整会话、计划、工具轨迹。
3. **Claude Code 的诚实感**：工具调用、参数、结果、diff 全部可见可折叠；危险操作显式确认；不伪造"已完成"。
4. **安全的视觉语言**：环境色（dev/staging/prod）、只读锁、破坏性红色、审批阻塞态。
5. **跨端同源**：桌面 token 与移动端共享数值；移动端重新编排而非简单缩放。

- 左右面板可拖拽调整宽度（5px 分隔条，双击复位），宽度记在本地；AI 面板可"展开为全宽"（工作区折叠为窄条）。
- 三栏宽度只由 `apps/desktop/src/lib/layout.ts` 一处决定（`computePaneLayout`，带单测）：中间工作区有硬地板
  `max(340px, 40% 可用宽)`，谁都不能吃掉它；左栏（连接树）是导航，上限 35% 可用宽与 460px 取小；
  右栏（AI 助手）是主功能，不设比例上限，能拿多少由「可用宽 − 中间地板 − 左栏实际宽度」推出，
  只受绝对上限 1200px 约束 —— 所以窗口越宽 AI 助手越大，2560 宽时能到 1200，窄窗口自动收小，
  全程保证中间不被挤压。
- 左侧连接栏可从标题栏按钮或 `⌘/Ctrl+B` 折叠，工作区随即占满；折叠状态同样记住。
- v0.3 对齐 Navicat 工业布局：标题栏 34、功能区 68、Tabs 31、数据/查询双行工具栏 35+36、行高 27；对象树按“表 / 视图 / 函数 / 查询 / 备份”分组；数据网格带行号与记录区间导航。
- 窗口宽度 <1000px：AI 面板变为覆盖抽屉（此时隐藏分隔条）；<720px：连接树隐藏。
- 自定义标题栏（Windows/Linux 用 `titleBarStyle: hidden` + traffic light 位置适配 macOS）。
- **右键全部接管**：全局阻止浏览器原生菜单。连接 / 库 / 表、标签页、结果单元格、图表卡片各有自己的菜单；其余区域给默认菜单（复制所选、剪切 / 复制 / 粘贴 / 全选、刷新结构、新建查询、AI 助手开关）。菜单组件只有一份（`ContextMenuHost`），位置自动收边。

### 5.1 表单控件由应用绘制，不用系统控件

系统控件只染 accent，底色 / 描边 / 弹层都归系统画，换肤跟不上——暗色面板上会出现系统白底。规则是：凡是用户能操作的表单控件，绘制权都在应用手里。

| 控件 | 实现 | 说明 |
|---|---|---|
| 下拉 | 共享 `Select`（`components/ui.tsx`） | 触发器沿用 `.select` 形态与 `data-testid`；菜单 `position: fixed` 脱离面板层级（`--bg-elevated` 底 + `--shadow-pop`）、按视口收边、下方放不下时向上翻、选中项打勾。`Option` / `OptGroup` 只是给 `Select` 读取的声明式标记，不产生 DOM。键盘：`↑↓` 移动、`Enter`/空格选中、`Esc` 关闭并把焦点还给触发器 |
| 可输入下拉 | 共享 `Combo` | 保留自由输入，建议列表复用 `.select-menu` 的主题；`datalist` 的建议弹层由系统绘制，不用 |
| 复选 / 单选 | `app.css` 全局接管 | `appearance: none` + `--bg-elevated` 底 + `--border-strong` 描边，选中态涂 `--accent`，对勾和圆点用 `::after` 画；`:indeterminate` 画横杠 |
| 数字输入 | `app.css` 全局接管 | `appearance: textfield` 杀掉系统 spinner（它是浅色的，跟暗色输入框对不上），数值直接键入 |
| 折叠块 | `details > summary` 全局接管 | `list-style: none` 撤掉系统三角，箭头换成 `::before` 画的边框角，随 `[open]` 旋转；自带 chevron 的折叠块（`.thinking` / `.execution` / `.memory-refs`）不再叠加 |
| 确认 / 输入框 | `AskDialog`（`askConfirm` / `askPrompt`） | 取代 `window.confirm` / `window.prompt`：系统对话框会把主题和语言整个甩开。返回 Promise，`Esc` 取消，压在右键菜单与下拉之上（`z-index 105`） |
| 选文件 | `.file-input` | 页面上只出现自己的按钮，`<input type=file>` 一律挂 `.file-input` 隐藏；裸挂会画出系统的「选择文件」控件，用 `setInputFiles` 驱动 |

- 面板内嵌的只读代码块统一用 `.code-block`（`--code-bg` 底，比面板暗一档），不再各处写内联样式。
- 尺寸变体走类名而不是内联 `style`：撑满用 `.input.grow` / `.textarea.grow`，成组控件的高度由所在容器的规则统一（如 `.memory-form .row .input, .select`），避免同一行里三个控件各写各的高度。
- 防回归：`npm run verify:controls`（`scripts/audit-form-controls.mjs`）静态检查五件事——所有 `var(--x)` 都有定义、CSS 里不留失效的 `select` 元素选择器、上述四类接管规则在场、`.tsx` 里没有 `alert(` / `confirm(` / `prompt(` 与原生 `select`/`option`/`optgroup`/`datalist` 标签、`<input type=file>` 都挂了 `.file-input` 且不用内联 `display:none` 藏控件。这些漂移只在运行时表现为“某个控件突然变回系统样式”，e2e 覆盖不到的面板（如表设计器）更是完全静默，所以必须有静态门。

## 6. Agent 面板（Claude Code 风格）

### 6.1 结构
```
┌─ AI 助手 ────────────────────────  [新会话] [历史] [记忆] [⤢] ┐
│  ● claude-sonnet · 自动模式 · 📎 schema · 1.2k tokens         │
├───────────────────────────────────────────────────────────────┤
│  ❯ 帮我看看上个月订单为什么下降了                             │
│                                                               │
│  ⏺ 我先了解 orders 表结构，再按周对比上月与上上月。            │
│                                                               │
│  ▸ 执行过程 · 3 步（折叠时只占一行，展开看工具与计划）          │
│                                                               │
│  **结论**：11 月第 2 周起下降 23%，主要是 …                    │
│                                                               │
│  ┌ 图表卡片（render_chart 的产物提到结论区，不复用执行步骤）──┐ │
│  └────────────────────────────────────────────────────────────┘ │
│                                                               │
│  ── 已完成 · 3 次工具调用 · 8.4s ──────────────────────────   │
├───────────────────────────────────────────────────────────────┤
│  ┌─────────────────────────────────────────────────────────┐  │
│  │ @ 引用表或库…                                           │  │
│  │                                                         │  │
│  │ /explain  /optimize  /schema  /backup  /clear           │  │
│  ├─────────────────────────────────────────────────────────┤  │
│  │ (＋) (权限:只读▾)        qwen3.8-flash-next · Default ▾ (⏎) │  │
│  └─────────────────────────────────────────────────────────┘  │
│    ⟳ 17 轮 714 步 220 tok/s │ ▤ 237M tok · 缓存命中 99.6% │ ◔ 52% │
└───────────────────────────────────────────────────────────────┘
```

### 6.1.1 输入卡与状态条（v0.5 改版）

输入区是一张**浮起的圆角卡**（18px 圆角、`bg-elevated` 底、内阴影 + 外部投影），内部不用分割线切段；卡片下方挂一行**卡外状态条**，纯展示、不可点。

- **胶囊工具行**：左下圆形 `＋` 打开「更多输入方式」弹层（引用表 / 添加图片 / 快捷指令 / 记忆 / Enter 提示），其后是权限胶囊；右侧是一枚**模型胶囊**（模型名 `·` 推理等级，读作 `qwen3.8-flash-next · Default`，对应参考图里的 `DeepSeek-V4.1-Flash ×0.1 Default`）与圆形发送键。模型与推理等级不再拆成两枚胶囊——档位是「这个模型的档位」，拆开会让人以为是两个独立开关。所有胶囊共用一套样式（无描边、27px 高、`bg-panel` 半透明底、hover 提亮、展开时 `bg-active` + 描边）。
- **模型胶囊宽度**：按内容自然宽度显示，最长占卡片 52%；只有模型名那一段可收缩走省略号，档位段 `flex: 0 0 auto` 不被挤压。右侧这组弹层一律向左展开（`right: 8px`），避免顶出卡片。
- **推理等级只在模型档案支持推理时出现**：`profile.reasoning` 为假或没有档位表时，胶囊只显示模型名，不给空档位。
- **档位的缺省档叫 `Default`，不叫「跟随服务商」**：`Default` 就是「不下发推理参数、用服务商自己的默认」，是档位菜单的第一项，也是胶囊未选档位时的显示值。清空档位时前端必须传 `reasoningTier: null`（传 `undefined` 会在 JSON 里整个消失，服务端浅合并当成「没改」，档位永远切不回 Default）；服务端收到 `null` 归一成未设置，不传该字段时保持原值，其它设置项保存不会顺带清掉档位。
- **弹层方向与两层结构**：一律从胶囊行**向上**展开并锚在左侧。合并后的模型胶囊弹层是第一层类别列表——`模型 <当前模型名> ›`、`推理等级 <当前档位> ›`，再一条分割线和「管理模型…」；点其中一行进入第二层该项的取值列表（顶部一行 `‹ 返回` 回到类别层）。选完模型或档位直接关闭整个弹层并把焦点送回输入框，不必再点一层「确定」。点卡片外或按 `Esc` 收起（`Esc` 一次关到底，不留半开的子列表）。权限/推理/模型不再是原生 `<select>`，`data-testid` 相应为 `agent-mode` / `agent-model-select`（合并胶囊）/ `agent-model-menu`（弹层）/ `agent-model-sub`（模型行）/ `agent-reasoning-tier`（推理等级行，仍在原语义上被 E2E 用来定位档位入口）。
- **发送键**：30px 圆形、`--agent` 实底、上箭头图标；运行中切换为红色停止方块。
- **状态条**（卡外**只有一行**，`--font-mono` 等宽数字；左侧是数据、右侧是风险提示，1px 竖线分隔数据组）：
  - `N 轮 M 步 X tok/s` —— 轮次是**用户发起的对话轮数**（中止/出错的回合同样计入，否则会出现「0 轮却跑了 30 步」读不通的组合）；步数是 runtime 真实的工具循环轮数，为 0 时隐藏；tok/s 以**模型调用耗时**（不含工具执行）为分母，避免生成速度被工具执行稀释。
  - `237M tok · 缓存命中 99.6%` —— 会话累计输入+输出；**一次调用都没成功时整格隐藏**（不显示 `0 tok`）；命中率 = `cacheHit / (cacheHit + cacheMiss)`，**服务商不返回缓存字段时这一格不渲染**，不显示假的 0%。
  - `◔ 52%` —— 上下文占用 = 最近一次模型调用的输入 tokens ÷ 模型档案里的 `contextWindow`；未配置窗口时不显示。
  - 缺数据即隐藏：一个指标都没有时左侧整段不出现，但行本身保留（容纳右侧提示），高度固定 18px 不抖动。
- **风险提示（右侧，常驻）**：`AI 可能出错，重要结论请自行核对`。运行中微微提亮。
  - **不写「按权限策略执行 / 均可审计」这类保证性文案**：那是替产品背书，真出问题反而成为把柄；权限档位已由左下胶囊直接标明（`全自动`/`只读`），无需文字重复。业界通行做法是反过来提示风险，不是承诺安全。
  - 审批弹窗里保留一句事实陈述（`本次调用将按当前权限档位执行，并记入审计日志`），同样不做「均可审计」的保证。

### 6.2 视觉与交互细节
- 回合顺序固定为「执行过程 → 结论 → 图表 → 汇总」：执行步骤默认折叠，运行中自动展开；结论与图表永远在执行块下方，图表不再塞进工具卡片里。
- 图表高度固定 350px（窗口太矮时只缩不涨，下限 140）；柱宽上限 72px，面板拖宽不会把柱子拉成色块。QueryView 里的图表仍随宽度增长，封顶 400。

- 用户消息：`❯` 青色前缀 + 青调气泡（左侧强调条、渐变底面、描边与轻阴影），与助手的无底色回答明确分层；右对齐不采用（保持扫描流）；支持多行。
- 助手文本：逐字流式；Markdown（标题/列表/表格/代码块/链接），表格横向滚动；代码块右上"复制/插入编辑器"。
- 工具卡：
  - 标题行：`⏺` 状态点（进行中呼吸动画→✓/✗/⏸），工具名 mono，耗时，摘要（如"120 行"）。
  - 展开：参数 JSON（语法高亮）、结果表格/错误、SQL 高亮 + "打开到编辑器"。
  - 写入类工具（DDL/UPDATE）：展示受影响对象与 diff（列增删绿色/红色背景）。
  - 审批等待：卡片黄色边框 + "等待授权…"，同时弹出审批弹窗。
- 计划清单：`✓ 完成 / ◐ 进行中 / ○ 待办`；折叠持久；每步完成时高亮 600ms。每轮只渲染最新一份计划。回合运行期间计划固定在输入框上方的活动状态条里（`done/total` + 当前步骤 + 最新动作，可展开完整清单），回答正文再长也不会把计划顶出视野；回合结束后计划收进「执行过程」。
- 思考/verbose：`▸ 思考过程（1.2s）` 折叠，默认收起（设置可常开）。
- 结束标记：`── 已完成 · N 次工具调用 · 8.4s · ↑1.2k ↓860 ──`；失败为 `── 已中止：原因 ──`。
- 空闲态：能力卡片（"解释这张表 / 找慢查询 / 生成测试数据 / 备份"）+ 最近会话。
- 快捷：输入 `/` 弹命令菜单；`@` 弹 schema 引用；`Shift+Enter` 换行；`↑` 召回历史输入；`Esc` 中止生成。
- 权限选择常驻输入框左下；只读时发送按钮变"询问"仍可对话但不能写。
- 断线：顶部横幅"Bridge 已断开，正在重连…"，输入禁用。

### 6.2.1 图表 / 体检卡片（v0.2）

- 图表：工具卡自动展开；柱状/折线/散点/热力/雷达用 SVG；饼图为圆角花瓣玫瑰图（Top 7 + 其他），标签分布在左右两侧，彩色引线先向外再横向折到标签，标签显示紧凑值与占比；热力图使用「底色 → 青绿 → 暖金/深青」顺序色阶，格内文字按填充亮度自动反色；密集分类轴自动旋转/竖排；hover 时选中柱/花瓣/点/热力格放大并带同色光晕阴影，折线显示竖向参考线和放大数据点，同时弹出即时数值 tooltip；底部显示 x/y 与“打开 SQL”。
- AI 图表选型：按数据结构校验类型（有序 X 才能折线、单度量 3–8 类才能饼图、多度量非负才能堆叠、双数值列才能散点、真实矩阵才能热力、3–8 个无序类别才能雷达）；不适配的类型在工具条禁用并显示原因，AI 初选不适配时自动降级到最合适的可用类型并提示。
- 体检/质量：`finding` 列表按 severity 排序，high=danger、medium=warning、low=accent；每条包含表名、具体数字、可执行 SQL 与“打开到编辑器”。
- 工具卡行为：普通读操作默认折叠；包含图表或 findings 的卡片自动展开。
- 首页仪表盘：连接/对象/数据量/Agent 指标条；最近查询、对象概览、AI 快捷能力、最近会话四块面板，减少大面积空白。

### 6.3 状态机（前端）
`idle → streaming → (awaiting_approval ⇄ streaming) → done | error | aborted`。中止时保留已生成内容并显示"已中止"。

- **连续审批走队列，不走单槽覆盖**：一个回合可以连着要求多次审批（建 5 张表 = 5 次 DDL），
  弹窗槽位却只有一个。`approval` 是当前显示的那条，`approvalQueue` 是排在它后面的，
  入队出队一律按 `approvalId` 生效（`lib/approvalQueue.ts`，纯函数带单测）。
  两条通道会抢这个槽位：SSE 推下一条与用户点击后的 `POST /approvals` 响应，谁先到不确定，
  所以**结算绝不能无差别清空槽位** —— 那样会把刚上屏的下一条一起抹掉，它挂在服务端等一个
  再也不会来的同意，直到 5 分钟超时被自动拒绝，表现成「后面的提问弹窗弹不出来」。
- 由此推出两条可见行为：① 弹窗里列出「还需确认 N 处」，让人知道后面还有；
  ② 只要队列里还有下一条，状态条保持「等待授权」，不闪回「运行中」（HTTP 迟到时同理）。
- 点「仅此一次」时 POST 在飞，弹窗保持原样（请求没送达就不假装已同意），期间到来的新审批进队列。
  `POST /approvals` 返回 404 表示服务端那边已经结算完了（超时自动拒绝 / 回合收尾 / 用户中止），
  按已处理收摊并放下一个进来，不弹错误；其它失败（5xx / 断线）保留弹窗并提示 ——
  不能静默放行，否则用户以为批过了，实际那一步被拒了。

## 7.5 仪表板视图（v0.4）

设计动机与接口见 [14 仪表板设计](./14-dashboard-design.md)。视觉与交互约定：

- 顶栏：`LayoutDashboard` 图标 + 「仪表板」+ 库选择器（板跟着库走，切库即切板）；右侧计数 `n / 12`、时间范围下拉（仅当板上标了时间列才出现）、刷新、从收藏导入、新建卡片、`让 AI 补一批`（primary）。
- 卡片网格：CSS grid 自适应两列，`span=2` 的卡片整宽；不做自由拖拽，靠卡片脚部的「前移 / 后移 / 加宽」排序。
- 卡片主体直接复用 `ChartView`（300px 固定绘图高、hover 提示、类型工具栏、`chartSuitability` 禁用不适配类型），外层的仪表板卡片不再重复画边框，避免出现两层卡片。
- 卡片脚部：来源标签（`AI 草稿` 用品牌青底、`AI · 已固定`、`收藏`、`手动`）、刷新状态、时间列下拉、固定/取消固定、宽窄、前后移、删除。图标按钮而非文字链，保持与工具条一致。
- 新建卡片（表单内联展开，不是弹窗）：顶部一句需求输入 + `AI 生成并预览`，下面可继续改标题 / SQL / 图表类型。生成成功后预览区按卡片同一套出图规则渲染图表，不可出图时退回前 6 行表格，并显示 `行数 · 耗时`；试跑错误内联展示，改了 SQL 会标「SQL 已修改，重新预览后为准」。脚部提供单独的 `预览` 与 `保存到仪表板`。
- 空态：一句解释「这块板属于当前这个库」+ 三个动作按钮（AI 生成草稿 / 从收藏导入 / 新建卡片），不留白。
- 草稿可见性：AI 生成的卡片默认未固定，头部有 `×` 一键丢弃全部草稿；用户固定过的卡片任何生成都不会动。
- 失败与降级：单卡失败只在脚部显示「失败」并保留上次快照，弹一条 warn toast，不整板报错；时间范围对没有该列的卡片回退为原查询，toast 说明「已按原查询展示」。

## 10.5 网络搜索设置面板（v0.4）

- 入口：设置 → 网络搜索（左栏搜索框可搜到「网络搜索 / Exa / Brave / SearXNG」）。
- 布局：单列滚动，最大宽度 760px；分组标题使用 12.5px 半粗，两列网格（≤720px 退化为单列）。
- 结构：摘要条（已启用后端 3/12、已配置密钥 0/7、刷新状态）→ 说明 → 免密钥后端（含一行可达性提示）→ 需要 API Key → 全局参数（含出站代理）→ 结果策略 → API 密钥 → 私有实例（SearXNG 地址 + 可选 Key）→ 立即测试 → 底部 重置状态/保存。

## 10.6 Agent 工具目录（只读）

- 入口：设置 → MCP 与工具 页底部，折叠面板「Agent 工具目录（只读 · 53 个）」。
- 内容：按能力分组列出全部第一方 Agent 工具——连接与结构 / SQL 执行与事务 / 多方言语句与检索 / 集合与文档 / 表结构与数据变更 / 分析、图表与体检 / 对比与迁移 / 运维 / 计划与记忆 / Skill / MCP。
- 每行：工具名（等宽）+ 风险徽标（read 绿 / write 金 / ddl 青 / destructive 红 / dynamic 中性）+ 工具说明（英文原文，两行截断，悬浮看全）+ 一行中文「可用条件」。
- 可用条件由风险等级与功能开关推导：只读=直接执行；写/DDL=连接只读时拒绝、询问模式审批；破坏性=始终审批；MCP/Skill 组额外标注总开关与「远程回合不下发」。`run_sql` 追加多语句开关说明，`mcp_call` 追加 server 反推说明。
- **只展示，不提供任何开关**：单个工具不可启停，避免做出「看起来能配其实不管用」的假设置项。分组与工具的一一对应由 `packages/core/src/agent/toolGroups.ts` 维护，core 测试断言 53 个工具既不遗漏也不重复，新增工具不补分组即测试失败。

## 11. 主题与品牌

- 暗色底是**中性石墨**（`#0b0d0d` → `#1e2323`，三通道接近，不带蓝调），像一台冷静的仪器。
- **品牌青 `#45c8c3` 只出现在交互与数据上**（焦点、选中、主按钮、主数据序列）；**金色 `#e0af63` 只做第二数据色**（多序列、预测线），不参与界面装饰，避免滑成「黑金」。
- Logo：数据库圆柱 + 对话气泡负形，青→金渐变（`--accent → --accent-2`），与品牌同源。
- 实心色块上的文字/图标统一用 `--on-solid`（暗色主题为墨色，浅色主题为白色），避免亮底上白字对比度不足。
- 语法着色随主题：关键字青、字符串橄榄、数字金、类型名蓝紫、注释中性灰斜体。
- 空状态插画用线稿 SVG（不引入位图），支持深色。
