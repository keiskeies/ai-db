## 2. 问题清单

### R-01（P1）≤720px 时功能区（Ribbon）横向溢出，页面被撑出横向滚动条

- **现象**：功能区 13 个模块按最小宽度 58px 排列，窄屏不换行、不滚动，直接撑宽根容器；页面出现横向滚动，右侧模块被裁掉。
- **实测**（功能区 `scrollWidth` vs 视口）：
  - 720px → 728px，溢出 **8px**（“仪表板”被裁）
  - 640px → 728px，溢出 **88px**
  - 480px → 728px，溢出 **248px**
  - 390px → 728px，溢出 **338px**（“用户”之后的“其它/查询/备份/自动运行/模型/仪表板”全部不可见）
- **连带**：390/414/480/640 下 `ribbon-dashboard` 等关键控件被其它按钮覆盖或移出视口（命中测试失败）。
- **截图**：`docs/test-artifacts/responsive/shots/d390x844-welcome.png`、`d720x720-welcome.png`。
- **影响**：窄窗口/移动 Web 无法访问“仪表板、模型、自动运行、备份”等模块，且整页横向滚动导致内容错位。
- **修复方向**：功能区改为可横向滚动（`overflow-x:auto`，隐藏滚动条），按钮 `flex:0 0 auto`；或窄屏折叠为“更多”菜单。

### R-02（P1）左右栏最大宽度是固定值，拖拽会把工作区压到不可用

- **现象**：左栏最大 460、右栏最大 760 是绝对像素，不随视口调整；两栏同时拖到最大时工作区被压缩甚至为 0。
- **实测**：
  - 1440×900 双栏最大 → 工作区 **210px**（数据网格只剩一列数字，表头被裁）
  - 1280×800 双栏最大 → 工作区 **50px**
  - 1024×768 双栏最大 → 工作区 **0px**，页面横向溢出 **206px**
  - 1024×768 仅左栏最大 → 工作区 **170px**；仅右栏最大 → **54px**
- **截图**：`shots/pane1440x900-both-max.png`、`shots/pane1024x768-both-max.png`。
- **影响**：拖拽本意是给数据/Agent 更多空间，但当前会把主工作区挤没，且产生横向滚动，用户需要手动找回宽度。
- **修复方向**：按视口动态计算两栏上限（预留最小工作区，如 340px），并让 splitter 的 `max` 使用同一上限。

### R-03（P1）窗口缩小时，已拖宽的左右栏不会收敛

- **现象**：在 1440 宽把左栏拖到 460、右栏拖到 760 后，把窗口缩到 1024：两栏仍保持 460/760，工作区 **0px**，页面横向溢出 **206px**。
- **截图**：`shots/pane1440x900-both-max.png`（宽屏态）与复现实验 `pane1440x900-shrink-1024`（审计 JSON）。
- **影响**：用户调整一次窗口大小就会进入“主界面消失”的状态，且偏好被持久化，下次打开仍复现。
- **修复方向**：渲染时按当前视口对两栏宽度做派生收敛（不改用户偏好），监听 `resize`；回到宽屏时恢复原偏好。

### R-04（P2）≤640px 时状态栏横向溢出，右侧信息被裁切

- **实测**（状态栏 `scrollWidth` vs 视口）：
  - 640px → 674px，溢出 **34px**
  - 480px → 674px，溢出 **194px**
  - 390px → 674px，溢出 **284px**
  - 360px → 674px，溢出 **314px**
- **现象**：`AI: 模型名`、`N 连接`、版本号被挤出视口；数据库路径过长且不省略，持续撑宽。
- **截图**：`shots/d390x844-welcome.png`（底部状态栏截断）。
- **修复方向**：路径列加省略号/限宽；窄屏按优先级隐藏模型、连接数、版本；状态栏 `overflow:hidden`。

### R-05（P2）≤720px 侧栏被强制隐藏，但切换按钮与 ⌘B 仍然存在且无效

- **现象**：CSS `@media (max-width:720px){ .sidebar{display:none} }`；此时标题栏的“隐藏/显示连接栏”按钮仍可点击，`Ctrl/⌘+B` 也仍绑定，但侧栏始终不出现。实测 390px 下点击前后 `isVisible` 均为 false。
- **影响**：移动 Web 无法切换连接/浏览对象树；按钮表现为“坏了”。
- **修复方向**：≤720px 改为抽屉式侧栏（覆盖在工作区上方，默认关闭），或隐藏切换入口并提供其它导航；同时隐藏左栏拖拽条。

### R-06（P2）右栏的响应式宽度被后加载样式覆盖，窄屏仍是固定 384px

- **现象**：`app.css` 中定义了 ≤1000px `width:min(440px,94vw)`、≤720px `width:100vw`，但 `industrial.css`（后加载）再次声明 `.agent-panel{width:var(--agent-w,384px); flex-basis:...}`，同优先级覆盖了媒体查询。实测 390px 下右栏仍为 **384px**，没有铺满 100vw；≤1000px 的 440px 上限也失效。
- **影响**：窄屏浮层宽度不符合设计，右侧留下 6px 缝隙；浮层与抽屉侧栏叠加时层级/宽度不可预期。
- **修复方向**：删除 `industrial.css` 中的重复宽度声明（保留背景等装饰），让媒体查询生效。

## 3. 非问题 / 通过项

- 移动 App 在 360/390/414/768 四档、配对/对话/数据/记忆/设置五页均为 0 溢出、0 越界、0 关键控件遮挡。
- 768–1920 的常态布局（未拖拽到极值）无溢出、无遮挡；窗口越宽，图表高度上限 400px 的约束仍生效（既有 E2E 覆盖）。
- 1440×900 双栏拖到最大时工作区 210px 属于 R-02 的边界表现，不再单列。
